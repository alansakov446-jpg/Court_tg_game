# 🏛 Telegram-бот «Суд»

Многопользовательский вымышленный судебный процесс: aiogram 3, SQLAlchemy 2 async,
PostgreSQL / Neon, Gemini. Python **3.12**. Без Dockerfile и дополнительных игровых таблиц.

## Быстрый запуск

1. Создайте бота у **@BotFather**, получите токен. Отключите **Group Privacy** через
   `/setprivacy`, затем заново добавьте бота в группу. Иначе бот не увидит обычные
   выступления, нарушения очередности и активность игроков. Разрешите отправку сообщений.
2. Создайте PostgreSQL в Neon. Используйте **direct connection**, не адрес с `-pooler`:
   процесс удерживает session-level advisory lock, несовместимый с transaction pooling.
3. Установите зависимости и задайте переменные **в окружении**:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt

   export BOT_TOKEN='токен от BotFather'
   export DATABASE_URL='postgresql+asyncpg://user:password@host/dbname?ssl=require'
   export GEMINI_API='key1,key2,key3,key4,key5'

   alembic upgrade head
   python main.py
   ```

   Не добавляйте реальные ключи в файлы репозитория, историю команд общего компьютера
   или логи. Приложение читает `os.getenv`/окружение; `.env` автоматически **не загружается**.
   При необходимости экспортируйте его безопасным способом перед запуском.
   URL из Neon с `postgresql://`, `sslmode=require` и `channel_binding=require` также
   нормализуется приложением: `sslmode` превращается в `ssl`, а `channel_binding` (его
   asyncpg не принимает и падает с `TypeError`) отбрасывается автоматически. SSL не отключайте.
4. В группе: `/game`, затем **каждый игрок, включая создателя**, нажимает «Вступить»
   и запускает бота в ЛС. Без этого Telegram запрещает боту первым присылать личные роли.

`RUN_SECONDS=0` (по умолчанию) — постоянная работа. `RUN_SECONDS=260` — ограниченный
сеанс тиков. `OFFSET_FILE` — путь offset, по умолчанию `.offset`.

## GitHub Actions

В **Settings → Secrets and variables → Actions → Repository secrets** задайте:

| Секрет | Значение |
|---|---|
| `BOT_TOKEN` | Токен @BotFather |
| `DATABASE_URL` | `postgresql+asyncpg://…` — direct URL Neon с SSL |
| `GEMINI_API` | `key1,key2,key3,key4,key5` — ключи разных проектов |

Workflow `.github/workflows/bot.yml` устанавливает Python 3.12, проверяет unit-тесты,
применяет миграции и запускает бота на 260 секунд. Offset восстанавливается и сохраняется
через `actions/cache` с уникальным ключом запуска. Игры и таймеры находятся в PostgreSQL,
не в кеше. Workflow можно запустить вручную через **Actions → Court bot → Run workflow**.
Плановые запуски работают только для workflow на **ветке по умолчанию** после слияния.

### Важное отличие от ТЗ: cron

GitHub Actions **не поддерживает интервал меньше 5 минут**. Поэтому вместо неработающего
`*/1 * * * *` используется `*/5 * * * *` и цикл long polling внутри каждого запуска.
Расписание может задерживаться, запуски могут стоять в очереди; это **не надёжный 24/7-хостинг**.
Во время простоя бот не отправляет напоминания. После пробуждения он проверяет сохранённые
дедлайны, не рассылает пачку пропущенных напоминаний и продолжает игру. Фазы после простоя
начинаются с новым временем, поэтому партия может длиться дольше. Запросы ИИ также могут
задерживать тик; точность таймеров не real-time. Для честных 30-секундных таймеров используйте
постоянный Python-процесс. Публичные репозитории могут терять расписание после длительной
неактивности; приватные расходуют Actions minutes. Кеш offset также расходует хранилище.

Не запускайте несколько poller-процессов с одним токеном. Workflow сериализован через
`concurrency`, а БД защищена advisory lock (в этой БД предполагается один бот).
Telegram-апдейты подтверждаются только после сохранения транзакции; гарантии exactly-once
нет: авария между отправкой сообщения, commit и записью offset может дать повтор сообщения
или команды. Без отдельной очереди/outbox транзакционно связать Telegram и PostgreSQL нельзя.

## Команды

| Команда | Действие |
|---|---|
| `/game [0..9]` | Лобби 2:30 и заданное число ботов; незанятые базовые роли добираются автоматически |
| `/extend 30` | Любой вступивший игрок продлевает до предела 5:00 от создания |
| `/startnow`, `/stop` | Создатель или администратор группы запускает / закрывает зал |
| `/leave` или кнопка | В лобби выход обратим; в партии бот остаётся навсегда |
| `/players` | Номера игроков для команд |
| `/role` | Роль, известные реплики и улики в ЛС |
| `/evidence` | В группе только публичные улики, в ЛС — доступные своей роли |
| `/balance` | Балансы сторон и текущая цена экспертизы |
| `/expert ID` | Оплатить экспертизу доступной улики и опубликовать трактовку |
| `/publish ID` | Приобщить свою скрытую улику к публичным материалам |
| `/call ID` | Прокурор, адвокат или судья вызывает свидетеля |
| `/ask ID вопрос` | Задать вопрос вызванному свидетелю |
| `/word ID` | Судья передаёт слово в пределах текущей фазы |
| `/next` | Судья завершает фазу, но не пропускает финальное слово и вердикт |
| `/object` или «Протестую!» | Протест против последнего публичного выступления |
| `/objection accept\|reject` | Решение судьи по протесту |
| `/recuse ID` | Заявить или поддержать отвод участника |
| `/return` | Вернуться после первого отстранения, если не было добровольного выхода |
| `/final текст` | Однократное финальное слово подсудимого, до 200 символов |
| `/vote guilty\|innocent` | Присяжный голосует в фазе вердикта; для тайного голоса используйте ЛС |
| `/verdict guilty\|innocent` | Судья выносит или пересматривает решение |
| `/games`, `/use ID` | В ЛС выбрать зал при участии в нескольких играх |
| `/say anon\|public текст` | Из ЛС присяжного судье: анонимно или с именем, не в общий чат |
| `/sayto ID текст` | Из ЛС одному присяжному через бота |
| `/help` | Справка |

Старые кнопки привязаны к конкретной игре и не действуют после её закрытия. Вступительная
ссылка содержит и `chat_id`, и ID игры. Участие по пересланной ссылке разрешено: проверки
членства в группе нет. Для контроля доступа не пересылайте ссылку за пределы группы.

## Правила и принятые решения

- Базовый состав: судья, прокурор, адвокат, подсудимый, **два свидетеля и три присяжных**.
  Роли случайны; при нехватке людей — боты, при избытке — дополнительные свидетели.
  Число живых игроков кодом не ограничено, но контекст Gemini и лимиты Telegram конечны.
- Фазы: преступление 60 с → обвинение 150 с → защита 150 с → прения 150 с →
  финальное слово 60 с → вердикт 150 с. Вместе с лобби — около 15 минут без задержек.
  В прениях слово можно передавать между сторонами. Свидетель выступает в пределах времени стороны.
- 30 секунд молчания активного оратора — предупреждение; ещё 30 — нарушение и передача
  слова / завершение выступления. Повторное нарушение ведёт к отстранению. Судья в фазах
  ознакомления и голосования не считается молчащим оратором. Подсудимого отвести нельзя.
- Реплики вне очереди: штраф стороне 10$, повтор — отстранение. У нейтральных ролей нет
  кошелька: штраф дисциплинарный, учитывается в счётчике нарушений. Сообщения не удаляются;
  для механики бот должен их получать (см. Group Privacy).
- Отвод поддерживает **строгое большинство действующих живых игроков, кроме цели**.
  Автор тоже считается; себя, подсудимого и уже играющего бота отвести нельзя. Роли истца
  в этом уголовном процессе нет. Бот наследует роль, доступ к её данным и историю выступлений.
  Первое отстранение обратимо, второе — навсегда. Добровольный выход сразу окончательный.
- «Невиновный при отводе» здесь означает участника **без зафиксированных нарушений**, а не
  невиновного подсудимого. В конце игры инициатор такого отвода платит 15$ своей стороны
  (или получает дисциплинарный штраф, если роль нейтральная). Это явно выбранное правило
  для неоднозначного пункта ТЗ. Голосование и инициатор сохраняются в `games.state`.
- Корректность протеста оценивает ИИ по процессуальным критериям, независимо от решения
  судьи. Три расхождения увеличивают дисциплинарный счётчик и дают основание для отвода.
  Если оценщик недоступен, решение судьи не оценивается. Это игровая оценка, не юридическая истина.
- Присяжных минимум три: они всегда образуют фракцию. Единогласие против судьи даёт ему
  30 секунд на пересмотр. Если он не пересмотрел, сохраняется его решение. Если решения судьи
  нет к дедлайну, используется большинство поданных голосов; ничья или отсутствие голосов —
  оправдание. `/say anon` скрывает имя от судьи, но не гарантирует анонимность от администратора БД.
- Стартовый бюджет **50$ на сторону в партии**, экспертиза 25$. В прениях ведущий может
  назначить цену 10–120$. Победа по вынесенному вердикту даёт +100$; это итог этой партии,
  не накопительный профиль между играми. Скрытая `truth` не передаётся ботам и не определяет
  автоматически судебный вердикт. Экспертизы возвращают заранее созданную трактовку улики,
  а не заново выдумывают факты.
- Дело содержит 5–7 улик. В прениях неопубликованные факты становятся публичными;
  трактовки остаются скрытыми до экспертизы. Генератор заполняет личные сведения каждой роли.
- Боты выступают, отвечают на допрос, дают финальное слово, голосуют и выносят вердикт.
  Боты сторон также выбирают экспертизу, вызов свидетеля или протест (не больше одного
  дополнительного действия на роль/фазу). Бот-судья разрешает протесты; переходами по дедлайнам
  управляет движок. Отводы и личную переписку присяжных инициируют люди, не автономный планировщик.

## ИИ, приватность и отказоустойчивость

`gemini-2.5-flash` → `gemini-2.5-flash-lite`; до пяти ключей в каждой модели. После HTTP 429
пара **ключ + модель** получает cooldown 60 секунд в памяти. Следующий ключ пробуется сразу;
при исчерпании модели начинается следующая. Lite имеет отдельную квоту. Перезапуск очищает
cooldown. Сетевые ошибки, невалидный JSON, пустые ответы и ошибки API пробуют следующий вариант.
Ключ передаётся заголовком, не URL; тексты ответов провайдера и ключи не логируются.

Если новое дело не удалось создать, зал сохраняется и повторяет попытку через минуту
(техническое ожидание может превысить лимит пользовательского `/extend`). Игра не стартует
с пустым делом. Если ИИ недоступен уже во время игры, бот использует нейтральную реплику,
голосует за недоказанность, пропускает необязательные действия; фазы продолжаются.

Нормализованный SHA-256 описания уникален в БД: **точные повторы отвергаются**. Последние
100 сюжетов передаются генератору с запретом смысловых повторов. Это не строгая гарантия
семантической уникальности всех возможных преступлений; для неё нужна дополнительная проверка.

У `evidence` и `statements` поле `visible_to_roles TEXT[]`. `public` — общие сведения.
Запрос контекста использует PostgreSQL `&& ARRAY['public', role]`, а не чтение всех записей
с фильтрацией в Python. Интерпретации не включаются в контекст до публикации экспертизы.
Личные сообщения присяжных видны только ролям отправителя/получателя. Бот роли не получает
`games.state`, `truth` или чужие личные факты. Все доступные сохранённые реплики включаются
в память — длинные партии могут превысить окно модели, тогда используется fallback.

Ведущий, напротив, создаёт всё дело и его скрытое решение. Ролевой бот знает не «всё дело»,
а ровно то, что знала его роль плюс публичный чат. Не отправляйте реальные персональные
или юридические сведения: доступный игровой контекст передаётся Google Gemini. Промпты
отделяют цитаты от инструкций, но абсолютной защиты от prompt injection и галлюцинаций нет.

## Структура и проверки

```text
main.py                 polling → транзакция апдейта → offset → игровые тики
ai/gemini.py            каскад и cooldown
ai/host.py              генерация дела, речь, выбор действия
game/                  правила, команды, лобби, фазы, экономика
db/models.py            games, players, roles, evidence, statements, economy
alembic/                версионируемая схема и уникальный индекс открытого зала
.github/workflows/      запуск бота и CI с отдельным PostgreSQL 16
```

```bash
python -m unittest discover -s tests -v
python -m compileall -q ai db game main.py alembic
alembic upgrade head --sql  # проверить SQL без подключения к БД
```

Unit-тесты не используют ключи и сеть: каскад HTTP замокан. Интеграционные тесты включаются
через `TEST_DATABASE_URL` и проверяют реальные PostgreSQL ARRAY, JSONB, сохранение игры,
замен и результатов после открытия новой сессии. **Они очищают все игровые таблицы!**
Используйте только отдельную одноразовую тестовую БД:

```bash
export TEST_DATABASE_URL='postgresql+asyncpg://user:password@localhost/court_test'
DATABASE_URL="$TEST_DATABASE_URL" alembic upgrade head
python -m unittest discover -s tests -v
```

CI делает это на отдельном PostgreSQL-сервисе, проверяет соответствие миграции моделям
через `alembic check` и обратную миграцию. Боевые секреты ему не нужны.

Перед запуском для игроков проверьте на тестовой группе вступление через ЛС, получение
обычных сообщений, `/game 9`, `/startnow`, `/expert`, отвод, финальное слово, голосование,
перезапуск процесса и восстановление offset. Живые Telegram, Neon и Gemini требуют ваших
секретов и сетевого доступа; unit-тесты не заменяют этот smoke-тест.
